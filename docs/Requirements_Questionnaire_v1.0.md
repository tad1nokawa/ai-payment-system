## A. 精算・手数料（経理・精算担当向け）

### A-1. 手数料率の適用タイミング
手数料率は「取引時点の料率」と「精算時点の料率」のどちらを適用しますか？

**背景**: 月途中に料率を変更した場合、取引時点適用なら旧料率の取引はそのまま。精算時点適用なら全て新料率で計算されます。

- [x] a) 取引時点の料率を適用（AQUAGATESはこちらの可能性が高い）
- [ ] b) 精算時点の料率を適用
- [ ] c) その他:

**✅ 確定: a) 取引時点の料率を適用**
> AG精算担当回答（2026-03-02）: AGではb寄り（締め日翌日に料率変更する運用）。月途中の料率変更は運用禁止としていた。新システムでは取引時に料率を記録し月途中変更にも対応可能とする。運用ルールとして「料率変更は締め日翌日を推奨」のガイダンスを残す。

### A-2. 精算サイクルの設定粒度
加盟店の精算サイクルはどのパターンがありますか？

- [ ] a) 月1回（月末締め翌月XX日払い）→ XXは何日？:
- [ ] b) 月2回（15日/月末締め）
- [ ] c) 週1回
- [ ] d) 加盟店ごとにカスタム設定可能
- [ ] e) 接続先ごとに締め日が異なるため接続先に依存
- [x] f) プリセット選択式（a,b,cの組み合わせ + 支払日設定）

**補足**: AQUAGATESの精算サイクルはどうなっていますか？:

**✅ 確定: f) プリセット選択式（a,b,cの組み合わせ + 支払日設定）**
> AG精算担当回答（2026-03-02）: a,b,cの組み合わせ（完全カスタムは基本なし）。締め日は月1/月2など少回数推奨（締め作業・振込手配の工数）。支払日は増えても精算工数への影響少。一部加盟店で10日支払いあり。→ 締め日パターン: 月1回（末締め）/月2回（15日+末日）/週1回。支払日: 加盟店ごとに選択可能（末日/10日/15日/20日/25日）。

### A-3. 精算バッチの実行時間
精算バッチは何時に実行しますか？

- [ ] a) 毎日AM2:00（リカーリングバッチの後）
- [x] b) 締め日翌日のAM2:00
- [ ] c) 手動実行のみ（M08画面から）
- [ ] d) その他:

**✅ 確定: b) 締め日翌日のAM2:00 + 再集計可能**
> AG精算担当回答（2026-03-02）: AGは日次積算→月末合計。フーバー（AG管理システム）はb)月末一括集計。日次積算はエラー修正が後からできない問題あり。フーバーは再計算可能な設計で、データ修正後に再集計→支払が可能。→ フーバー方式採用: 締め日翌日AM2:00に一括集計。M08から手動再集計ボタン（エラー修正後の再処理用）。再集計時は確定前の精算データを上書き。

### A-4. 手数料の計算構造
手数料は以下のどの構造ですか？

**背景**: TR手数料（トランザクションフィー）が取引ごとの固定額なのか、料率なのかで計算が変わります。

- [ ] a) 決済手数料率（%）のみ（例: VISA 3.25%）
- [ ] b) 決済手数料率（%）+ TR手数料（固定円/件）（例: VISA 3.25% + 30円/件）
- [ ] c) ブランド別 × 接続先別で異なる複合レート
- [x] d) 二層構造（加盟店手数料 + アクワイアラ原価）

**AQUAGATESの手数料構造を教えてください**:

**✅ 確定: d) 二層構造（加盟店手数料 + アクワイアラ原価）**
> AG精算担当回答（2026-03-02）: 加盟店手数料 = (決済代金×加盟店手数料率) + TR手数料 + 返金手数料 + CB手数料 + 振込手数料。アクワイアラ原価 = (決済代金×アクワイアラ手数料率) + TR手数料 + 返金手数料 + CB手数料 + 振込手数料（接続先によりリバーサル手数料等あり）。各項目は決済種別×接続先ごとに設定可能。PSP利益 = 加盟店手数料 − アクワイアラ原価。

```
入金額 = 決済高 − 手数料 − TR手数料 − CB差引 − リザーブ留保 + リザーブ解放
```

- [ ] a) 合っている
- [x] b) 違う（正しい計算式を記載）:

**✅ 確定: b) 修正版計算式**

### A-6. リザーブ解放のタイミング
リザーブ（留保金）の解放は何を基準にしますか？

- [ ] a) 留保日から180日経過で自動解放

- [ ] d) a + c の併用（自動解放 + 手動解放も可能）

**✅ 確定: e) 精算時に自動解放 + 手動調整**
> AG精算担当回答（2026-03-02）: AGはe) 精算サイクルでの順次解放 + 手動のミックス。180日経過後の報酬支払タイミングで解放 + 手動でリリース検討。→ 留保期間経過後、次の精算タイミングで自動解放リストに表示 → 運営が確認して実行。手動での保留延長・即時解放も可能。

### A-7. 祝日・休日の精算処理
精算日（入金日）が祝日・休日の場合はどうしますか？

- [ ] a) 翌営業日にスライド
- [ ] b) 前営業日にスライド
- [ ] c) 暦日通り（金融機関が対応していれば）

### A-8. 精算エラー時の運用
精算バッチでエラーが発生した場合の運用フローは？

**背景**: 口座情報エラー、金額不整合、接続先からの応答なし等のケースです。

- [ ] a) エラー分のみ例外キュー（M02）に送り、正常分は精算実行
- [x] b) 該当加盟店の精算全体を保留にして手動確認
- [ ] c) バッチ全体を停止して手動対応
- [ ] d) その他:

**✅ 確定: b) 該当加盟店の精算全体を保留**
> AG精算担当回答（2026-03-02）: AGはエラーアラートなし、人間が突合して手動修正。フーバーは再計算可能設計でデータ修正→再集計→支払。b)推奨。a)で部分支払すると保留分管理の工数 + 振込手数料の二重徴収調整が必要。→ エラー発生 → 該当加盟店を保留 → M02例外キューに通知。運営がデータ修正後、M08から再集計→支払実行。他加盟店の精算は正常実行。
